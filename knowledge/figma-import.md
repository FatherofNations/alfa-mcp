# figma-import — выгрузка данных из Figma

> Прочитай ПЕРЕД началом разбора макета. Здесь все грабли выгрузки,
> собранные на реальных проектах. Инструмент — официальный Figma MCP
> (`get_design_context`, `get_variable_defs`, `get_screenshot`,
> `get_metadata`, `download_assets`, `use_figma`).

## Правило №1: данные — только из Figma MCP

Размеры, цвета, отступы, шрифты, тексты берём из `get_design_context` /
`get_variable_defs`. **Не со скриншотов.** Скриншот (`get_screenshot`) —
только визуальный эталон для последующего диффа, не источник значений:
глазомер по PNG даёт ±2px и «примерно такой серый», а design context —
точные `rgba` и целые пиксели.

## Обрезка контекста: дозапрашивай по под-узлам

`get_design_context` обрезается примерно на **25k токенов**. Большой фрейм
(целый дашборд) одним вызовом не влезает — выдача молча обрывается, и
низ макета «исчезает».

Правильный цикл:

1. `get_metadata(nodeId=фрейм)` — получить дерево детей с id, именами,
   размерами (дёшево).
2. По каждому крупному ребёнку (сайдбар, шапка, панель, лента) — отдельный
   `get_design_context(nodeId=ребёнок)`.
3. Если и ребёнок обрезается — спуститься ещё на уровень.

## Листинг страниц: get_metadata может врать

`get_metadata` без `nodeId` может показать **только одну страницу** файла.
Полный список страниц и фреймов добывается read-only кодом через `use_figma`:

```js
// перечислить все страницы и их верхнеуровневые фреймы
const pages = figma.root.children.map((p) => ({
  id: p.id,
  name: p.name,
  frames: p.children.map((f) => ({ id: f.id, name: f.name, type: f.type })),
}));
```

## Инстансы с instance-path id (`I123:45;678:90`)

`getNodeByIdAsync("I…;…")` возвращает **null** — такие id не резолвятся
напрямую. Обходить дерево от ближайшего «настоящего» родителя:

```js
// найти под-узел инстанса и выгрузить его картинкой
const parent = await figma.getNodeByIdAsync("123:45"); // родитель с обычным id
const walk = (n) => {
  if (n.id === targetId) return n;
  for (const c of n.children ?? []) { const hit = walk(c); if (hit) return hit; }
};
const node = walk(parent);
const bytes = await node.exportAsync({ format: "PNG", constraint: { type: "SCALE", value: 2 } });
return figma.base64Encode(bytes);
```

## Пустые экспорты (1×1 PNG)

Некоторые узлы рендерятся пустыми в изоляции — `get_screenshot` по ним
отдаёт 1×1 или полностью прозрачный PNG (типично для узлов, чей вид
зависит от масок/фонов родителя). Данные по таким узлам тянуть
`get_design_context` по каждому под-узлу отдельно, а картинку — экспортом
**узла-родителя** с последующей обрезкой.

Проверка непустоты обязательна: у PNG посчитать bbox по альфе; если пусто —
перевыгрузить родителя. Тул `process_assets` ловит такие файлы автоматически.

## Макет — живой документ

Дизайнер переделывает фреймы, узлы переезжают и меняют id (реальный
случай: search-кнопка `199:31967` → `199:56451`). Правила:

- при повторном заходе в файл — сначала свежий `get_metadata`, потом работа;
- не доверять node-id из своих старых заметок/кода;
- если узел «пропал» — искать по имени в свежем дереве.

## Недоступные тексты компонентов

Текст из компонентов-статусов бывает недоступен (компонент `Status` без
текстового лейбла в выдаче). Не блокироваться: поставить осмысленный
дефолт по смыслу макета и **зафиксировать отступление** в handoff-документе
(раздел «осознанные отступления»).

## Быстрый пайплайн ассетов (ключ к скорости)

Выгрузка ассетов — самая долгая часть работы. Правильный цикл сводит её
к **двум операциям** без потери качества:

1. **Один проход по design context** — собрать СПИСОК всех ассетов фрейма
   заранее (иконки → svg, фото/иллюстрации → png), с node-id и осмысленными
   camelCase-именами. Не выгружать «по мере вёрстки» — каждый возврат в
   Figma стоит минут.
2. **Один батч `download_assets`** (Figma MCP) сразу в `public/assets/figma`
   со своими именами. Не по одному узлу! Батч из 30 иконок — один вызов.
3. **Один вызов `process_assets`** (proto-forge) на всю папку СРАЗУ после
   скачивания, до вёрстки: SVG-санитайзер, детект пустых экспортов,
   flood-fill чистка запечённых фонов (по списку имён), lossless WebP.
   После него в отчёте видно, какие узлы надо перевыгрузить.

Правила:

- `process_assets` запускать ДО вёрстки: png может стать webp — пути
  в `<img>` пишутся уже по факту.
- Пустой экспорт (1×1 / alpha=0) → перевыгрузить **узел-родитель** тем же
  `download_assets` и обрезать; совсем упрямые узлы — `use_figma` +
  `exportAsync` + `base64Encode` (см. выше про инстансы).
- Asset-URL от Figma живут **7 дней** — не хранить их в коде, скачивать сразу.
- У `python urllib` на figma-CDN стабильно падает SSL — качать через `curl`
  или Node `fetch`.

## Чек-лист перед вёрсткой

- [ ] `get_metadata` по фрейму свежий (не из прошлой сессии)
- [ ] design context собран по всем крупным под-узлам, ничего не обрезано
- [ ] `get_variable_defs` снят → передан в `extract_tokens`
- [ ] эталонный скриншот фрейма сохранён (для диффа)
- [ ] список ассетов собран заранее → ОДИН батч download_assets
- [ ] process_assets прогнан, пустые экспорты перевыгружены
- [ ] недоступные тексты/иконки зафиксированы списком отступлений
