# pixel-perfect — методика точной вёрстки

> Как получить расхождение с макетом только в font-hinting, а не «похоже».

## Эталон и сверка

1. **Эталон**: `get_screenshot` фрейма из Figma → PNG (масштаб 1x, без обвесов).
2. **Кандидат**: headless Chrome скриншот той же геометрии,
   **строго по `http://localhost`** — по `file://` часть `<img>` стабильно
   не дорисовывается к моменту кадра.
3. **Дифф**: полупрозрачный бленд эталона и кандидата:

```python
from PIL import Image
a = Image.open("figma.png").convert("RGBA")
b = Image.open("local.png").convert("RGBA").resize(a.size)
Image.blend(a, b, 0.5).save("diff.png")
```

Цель: в бленде расходится только сглаживание шрифтов (font-hinting ОС).
Двоение контуров = ошибка геометрии; сдвиг блока = ошибка отступов.

```bash
# кандидат: headless chrome, окно = размеру фрейма
chrome --headless --disable-gpu --screenshot=local.png \
  --window-size=1440,1024 http://localhost:3000/
```

## Byte-perfect перенос, поведение поверх

Крупную статичную разметку (сайдбар, шапка, лента, гриды карточек)
переносить **байт-в-байт**, не переписывать «по мотивам»: каждая ручная
перепечатка — источник дрейфа на 1-2px. Поведение (клики, анимации,
состояния) навешивается поверх скриптами/хуками, не меняя разметку.

Отступления от макета — **только по явной просьбе**, каждое фиксировать
в handoff списком «осознанные отступления» (что, почему, где).

## Скриншоты анимаций: транзишены в headless заморожены

CSS-транзишены в фоновой вкладке/headless **не тикают**. Приёмы:

| Что проверить | Приём |
|---|---|
| Конечное состояние | инжект `*{transition:none!important}` → элемент мгновенно в финале |
| Середина транзишена | `transition-duration:60s; transition-delay:-30s` → элемент застывает ровно в середине |
| Кадр CSS-анимации на t | `animation-delay:-t; animation-play-state:paused` |
| Ранняя фаза JS-анимации | обычный скриншот через ~0.3s wall-clock; `--virtual-time-budget` НЕ использовать — он сдвигает часы JS |

## Дифф одного виджета

Для точечной сверки виджета: SVG-экспорт узла из Figma → наложить на
скриншот области тем же блендом. Быстрее, чем гонять весь фрейм.

## Глазами эти дефекты не видно — мерить раны

Сравнение картинок «рядом» не работает. На реальном дашборде пять
дефектов из пяти выглядели правдоподобно и нашлись только замером:

| Дефект | Ошибка | Чем поймали |
|---|---|---|
| суммы прижаты влево, а не вправо | **75 px** | раны: эталон 1356..1455, локальный 1431..1529 |
| шрифт меню 14, а не 16 | ширина 118 против 133 | ширина рана растёт с длиной строки |
| у иллюстрации потерян внутренний трансформ | ~4 px + масштаб | карта горячих блоков |
| потерян замыкающий пробел в «… RUB » | 3 px | позиции ранов |
| сжатую колонку обрезает не тот элемент | семантика | ран заголовка не сходится |

Первый показателен: колонка сумм «выглядит правильной», потому что все
суммы одной длины. Пока демо-числа одинаковые, глаз не поймает это никогда.

**Тул:** `parity_check({ url, reference, width, height })` — снимает оба
кадра, считает метрики, карту горячих блоков и смещения текстовых ранов.
`ignore` — прямоугольники под хром прототипа (FAB панели tools) и зоны
осознанных отступлений, чтобы они не топили настоящие находки.

Как читать вывод:

- сдвиг у ОДНОГО блока в строке → выравнивание/паддинг этой ячейки;
- «ширина +N», растущая с длиной строки → не тот размер шрифта или
  letter-spacing;
- одинаковый сдвиг у ВСЕХ блоков → уехал контейнер, а не содержимое;
- блок не нашёл пары → элемент отсутствует либо уехал больше чем на 200px.

## Дифф ПОСЛЕ КАЖДОЙ секции, а не один раз в конце

Главный вывод по скорости. Ошибка в общем правиле — размер шрифта меню,
выравнивание ячейки, шрифт контентной зоны — размножается по всей
странице. Пойманная на первой секции, она стоит одной правки; пойманная
в конце — перепроверки всего сделанного.

## Иллюстрации: внешний бокс и внутренний лист — разные вещи

В Figma картинка внутри фрейма часто крупнее его и со сдвигом:

```
<div class="…size-[116px] …">                              ← бокс, overflow hidden
  <img class="…size-[105.23%] left-[-3.35%] top-[-0.63%]"> ← лист
```

Переносить оба уровня. Если применить геометрию бокса прямо к `<img>`,
картинка уедет на несколько пикселей и станет меньше — в бленде это
видно как горячий блок без смещения текста. Проверять по bbox: у верного
переноса `dx = dy = 0`.

## Порядок работы

1. Снять эталон фрейма.
2. Сверстать скелет (геометрия, без текстур) — первый `parity_check`.
3. Довести отступы/размеры до совпадения контуров.
4. Залить контент и стили текста — `parity_check` после КАЖДОЙ секции.
5. Финальный отчёт приложить к handoff.

## Чек-лист

- [ ] эталон снят с того же масштаба, что и вьюпорт кандидата
- [ ] кандидат снят по http://localhost, не file://
- [ ] кадр снят ПОСЛЕ окончания канон-ревила (иначе ложный сдвиг всей страницы)
- [ ] `parity_check` не показывает смещений текстовых ранов
- [ ] в бленде расходится только сглаживание шрифтов
- [ ] статичная разметка перенесена byte-perfect, не «по мотивам»
- [ ] отступления перечислены в handoff
