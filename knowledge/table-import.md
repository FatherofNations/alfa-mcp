# table-import — перенос таблиц из макета

> Читай ПЕРЕД разбором любой секции с таблицей. Дашборды Альфа-Бизнеса —
> это в основном таблицы, и именно на них выгрузка макета стоит дороже
> всего, а вёрстка чаще всего расходится с макетом незаметно для глаза.

## Почему таблица — особый случай

`get_design_context` разворачивает **каждого** повторяющегося ребёнка
целиком. Таблица на 14 строк — это 14 копий одного поддерева ячеек.
Замеры на реальном дашборде (283:196383, «Финансист»):

| Узел | Символов в ответе | Полезного |
|---|---|---|
| `get_metadata` корня | 101 160 | ~8 строк дерева |
| «Счета», 7 строк | 75 419 | геометрия 1 строки + 6 заголовков |
| `[D] SideMenu`, 14 пунктов | 87 233 | 14 подписей + 1 размер шрифта |
| строки «Ленты», 14 строк | 131 865 | 14 строк × 5 полей |

Итого ~396 000 символов, из которых пригодилось ~2%. Ни один из этих
ответов не влезает в лимит контекста.

## Порядок

1. **`get_metadata`** на корневой фрейм. Если ответ не влез —
   `digest_design_context(file, mode:"layout")`. Получишь дерево с
   схлопнутыми повторами: `14× BodyRow 1331×49, шаг y=49, x чередуется
   0/6` (чередование x — это вставленная подложка зебры).
2. **`get_design_context` на СЕКЦИЮ таблицы** (не на строку и не на весь
   экран). Ответ почти наверняка не влезет — это нормально.
3. **`digest_design_context(file, mode:"rows")`** — вернёт:
   - подложку каждой строки (высота, фон, скругление, инсет) — по ней
     читается зебра и её чётность;
   - геометрию ячеек первой строки (ширины, паддинги, выравнивание);
   - матрицу текстов всех строк с ПОДСВЕЧЕННЫМИ невидимыми пробелами.
4. **`digest_design_context(file, mode:"text")`** на ту же выдачу, если
   нужна типографика: вернёт стили сгруппированно. Здесь ловится
   «шрифт контента ≠ шрифт хрома».
5. Вёрстка → **`parity_check`** на секцию.

## Полоса ячеек шире карточки

Типовая конструкция макетов Альфы: строка вставлена внутрь карточки на
6px (`left:6 right:6`), а полоса ячеек внутри строки вылезает обратно
(`left:-6 right:-8`). Итог: **ячейки шире карточки на 2px**, лишнее
обрезается `overflow: hidden` карточки.

Значит:
- подложка зебры = строка (инсет 6px, скругление 12);
- сетка колонок считается от **1331**, а не от 1329;
- сумма фиксированных ширин + flex-колонка должна давать 1331, иначе
  где-то потеряна колонка.

```css
.rows  { position: absolute; left: 0; right: -2px; }   /* 1331 при карточке 1329 */
.row   { position: relative; height: calc(var(--row-h) + 1px); }
.row::before {                    /* подложка зебры — отдельным слоем */
  content: ""; position: absolute; inset: 0 calc(var(--inset) + 2px) 0 var(--inset);
  border-radius: var(--row-radius); background: var(--zebra);
}
```

## Шапка колонок часто НЕ совпадает с телом

Регулярная ситуация: заголовки взяты из другого пресета, чем строки.
Реальный случай — шапка `52·701·132·232·132·flex·48`, тело
`52·flex·132·232·132·200·52`. Из-за этого «Дата» стоит правее дат, а
последняя колонка сжата до 36px и её заголовок обрезан.

**Это дефект макета, а не твой.** Порядок:

1. Перенести как есть — pixel-perfect значит воспроизвести и это.
2. Записать в «осознанные отступления» handoff отдельным пунктом.
3. Если есть панель tools — вывести тумблер «шапка по колонкам»,
   по умолчанию ВЫКЛЮЧЕННЫЙ (чистая ссылка = макет 1:1).
4. Сказать пользователю в отчёте. Не «чинить» молча.

Ширины шапки и тела держать в CSS-переменных, тогда тумблер — три строки:

```css
.hc-name   { flex: 0 0 701px; }
.hc-amount { flex: 1 1 0; }
body[data-alignhead="1"] .hc-name   { flex: 1 1 0; }
body[data-alignhead="1"] .hc-amount { flex: 0 0 var(--tbl-sum); }
```

## Кто обрезает переполнение

Если колонка сжата, важно понять, **чем** обрезан её заголовок. В макетах
Альфы ячейка действий (шестерёнка) имеет белую заливку и лежит выше
соседей — она и закрывает переполнение. Воспроизводить надо именно это,
а не `text-overflow: ellipsis`: результат отличается на глаз.

```css
.hc-title { flex: 1 0 auto; }            /* grow 1 / shrink 0 — как в Figma */
.hc-act   { position: relative; z-index: 1; background: #fff; }
```

Признак, что угадал правильно: в `parity_check` ран заголовка совпадает
с эталоном до пикселя.

## Выравнивание в ячейке — проверять, а не предполагать

Числовая колонка часто выглядит выровненной по правому краю, а на деле
блок суммы — `shrink-0` внутри ячейки с `items-start`, то есть прижат
**влево**. Разница не видна, пока все суммы одной длины, и вылезает на
первом же реальном числе.

В `mode:"rows"` смотри поле выравнивания ячейки. При сомнении — считай:
`x ячейки + padding-left` должен совпасть с началом текста в эталоне.

## Невидимые пробелы

В числах Альфы разряды разделены **U+205F** (medium math space), а перед
`₽` стоит **U+2009** (thin space). Обычный пробел уже другой ширины —
строка разъедется на несколько пикселей, и `parity_check` это покажет.
`digest_design_context` подсвечивает их: `⎵` = U+205F, `⎸` = U+2009,
`⍽` = NBSP. Переносить в код ровно те символы, что в макете.

Замыкающий пробел тоже значим: `«49 720 000,00 RUB »` при
`justify-content: space-between` сдвигает текст на ~4px. В JSX обычный
пробел на конце схлопнется — ставить `&#8201;` / `&#160;`.

## Тексты компонентов, которых нет в выдаче

Компонент `Status` (чипы `TAG`, `IDENTIFIER`, …) не отдаёт текст лейбла
в design context — приходит только `<Status size="20" shape="Rounded" />`.
Так же ведут себя другие обёртки core-ds.

Порядок: взять подписи с эталонного скриншота, метрики чипа подобрать
по нему же, и **записать в «осознанные отступления»** — это единственное
место, где скриншот легально становится источником.

## Чек-лист перед сдачей таблицы

- [ ] сумма ширин колонок = ширине полосы ячеек (обычно карточка + 2px);
- [ ] шаг строк и высота ячеек совпали с макетом (`шаг = высота + 1`);
- [ ] зебра на той же чётности, что в макете (сверить по инсету строк);
- [ ] выравнивание числовых колонок проверено расчётом, а не на глаз;
- [ ] невидимые пробелы перенесены как в макете;
- [ ] расхождения шапки и тела воспроизведены и записаны в отступления;
- [ ] `parity_check` по секции: смещений текстовых ранов нет.
